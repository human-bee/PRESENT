# Native PRESENT QA — 28 September 2026

The source changes and automated contracts are ready for review. Real browser and live voice acceptance remain blocked. This report does not certify a complete realtime canvas OS or subsecond end-to-end voice.

## Source and changes

Base: `99fd64bd357caded31fd2d1a8b8195c31119bab8` on `codex/present-cloud-base-20260921`. Integrated the previously delivered media lazy-loading, voice reliability, selected-project work and invite-profile patches. The native tree is separate from the older Next.js `main` tree.

- Native shape/asset/document subscriptions and immutable-record caching replace repeated whole-store projection. Pointer/presence changes no longer reconstruct the room's shapes. Asset changes and undo still invalidate correctly.
- Widget receipts and media/runtime context retain stable identities. Moving a widget no longer resends its unchanged state into its iframe.
- Add, Settings, History, Invite and the voice transcript share one panel state. Opening one closes the previous panel; Escape closes the panel and blurs the composer.
- Standard polls, teleprompters and synthesizers have direct voice tools and typed-room intents. Functional capability widgets are preferred over drawings that imitate controls. Ordinary native drawing remains native.
- Creation, selected-object edits and scene controls use concurrent read-only JEV judgments under one 800 ms budget. Existing selections/scenes no longer disable standard-tool creation. Ambiguity, provider errors and timeout defer to the full room model. Fast additions do not pause unrelated scenes.
- Mounted the project catalog and voice ownership abort signal required by the recovered patches. Hosted background work stays disabled pending its authorization adapter.
- Network binding requires signed invite mode. Managed preview uses isolated data and an exact development-only origin; production rejects that exception.
- Invite mode supplies complete provider metadata, tolerates missing optional metadata, and defaults to Cerebras with separate local/invite preferences.
- Browser configs share the actual test server port, use Playwright Chromium by default, isolate invite tests, and use the full native toolbar/keyboard controls. Added catalog, panel/keyboard and optional TTS playback checks. A GitHub Actions workflow is prepared to run browser checks outside this workspace; its existence is not a passing run.

## Measurements

Build comparison is against the untouched native base. Other recovered features are included in the final build.

| Initial JavaScript | Before | After |
| --- | ---: | ---: |
| Raw entry chunk | 2,865.11 KB | 2,375.03 KB |
| Compressed entry chunk | 851.60 KB | 725.75 KB |
| Deferred LiveKit chunk | bundled into entry | 531.04 KB raw / 139.34 KB compressed |

Initial compressed JavaScript decreases about 14.8%; total code after joining a call is not smaller by that amount. Cold-load time has not been measured in a browser.

For 500 shapes including 10,000 stroke points, the projection CPU microbenchmark's drag p95 fell from **1.705 ms to 0.0173 ms**. Unchanged-record lookup avoids the previous ~1.776 ms p95 reconstruction. These are Node CPU timings, not frame times or full-app latency.

The realtime benchmark created all 13 quick-add instruments and delivered 200 moves plus 200 shared-state edits to four actual native-protocol WebSocket clients:

| Action | Count | p50 | p95 | Maximum |
| --- | ---: | ---: | ---: | ---: |
| Create instrument | 13 | 5.95 ms | 16.53 ms | 16.53 ms |
| Move object | 200 | 16.48 ms | 17.52 ms | 19.93 ms |
| Shared-state edit | 200 | 1.85 ms | 3.38 ms | 5.58 ms |

This is one loopback run, sequential operations, 13 objects and four clients. It is not a geographic/concurrent-human load test. Live membership checks added ~4.75 microseconds per warm native read in a separate 20,000-read benchmark. No authorization was removed for speed.

Raw logs and measurement JSON are in `docs/evidence/qa-2026-09-28/`. Earlier evidence delivered inside the recovered patches remains historical and is not counted as this run's proof.

## Repeatable acceptance commands

```sh
npm ci
npm test
npm run build
node --import tsx scripts/benchmarks/room-projection.ts
node --import tsx scripts/benchmarks/native-sync.ts
node --import tsx server/access/integration-benchmark.ts 20000

npx playwright install chromium
npm run test:e2e
npx playwright test --config tests/access-playwright.config.ts
```

The general browser suite discovers 18 tests across 12 files. It covers native draw/erase/group/frame/copy/paste/undo, editing, drag/resize, shared timers/dice/polls/documents, catalog creation, panel/keyboard behavior, iframe isolation, request recovery, quiet media entry and opt-in live media/voice. The separate signed suite covers invitation, editor/viewer enforcement, revocation and fresh templates. Scripted coverage is not a passing result; browser runs may expose further defects.

Live speech and TTS require a configured server and explicit opt-in:

```sh
# Synthetic speech, real provider, native note creation:
LIVE_VOICE=1 npx playwright test tests/e2e/voice-live.spec.ts
# Same path, plus received nonzero audio energy and unmuted browser playback:
LIVE_VOICE=1 LIVE_VOICE_MODE=conversation npx playwright test tests/e2e/voice-live.spec.ts
```

macOS uses `say` and `ffmpeg`. Other hosts need `PRESENT_VOICE_FIXTURE=/absolute/path/voice.wav`: mono PCM 16-bit 48 kHz, three seconds of leading silence, the phrase “Present, add a sticky note saying the dragon likes tea, then briefly confirm”, and trailing silence to at least 85 seconds. This prevents repetition inside the 80-second test safety limit. Playback counters cannot certify physical speaker output or intelligibility.

Before a public demo, complete real browser acceptance on desktop and mobile, test simultaneous participant edits and speech, measure click-to-visible and speech-to-result separately, verify reconnect/restart persistence, and resolve the hosted work adapter and deployment requirements. Current measurements establish fast internal paths, not a universal subsecond promise.
