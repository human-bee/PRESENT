# P1 causal scene tracing and Decisions preflight

A valid room request now has one request ID across accepted, planning, provider dispatch/result, validation, native transaction, scene commit and terminal completion/failure. Receipts contain wall clocks and monotonic elapsed/previous-stage durations, sequence numbers, selected provider, exact model when confirmed, and native document clock/transaction revision. Concurrent requests use separate async contexts. Caller abort and deadline expiration have separate terminal stages. Invalid repair attempts are visible without retaining rejected output or error messages.

`logs/canvas-requests.jsonl` contains version 1 allowlisted receipts. The room bearer token is hashed; no prompt, screenshot, actor, generated text, provider error message, environment value or credential is included. Logs rotate at 5 MB into one previous file. Current files are mode 0600. Diagnostics and sink failures cannot change a successful operation. Existing pre-P1 files are not rewritten or deleted; old unversioned entries are historical diagnostics, not this receipt contract.

Codex dispatch is recorded immediately before `turn/start` and its model is confirmed by the accepted `thread/start` response. An OpenAI API dispatch names the requested alias; only the validated terminal response records its exact alias or dated snapshot as confirmed. Cerebras dispatch is labeled requested because its adapter does not expose verified returned model metadata. TypeSafe fast-route confirmation follows literal accepted Jev response validation. No trace event claims that discovery alone proves a generated response.

The optional operator smoke fence is enabled only with all three env values: `PRESENT_NATIVE_SCENE_BUDGET_FILE` (absolute private path), `PRESENT_NATIVE_SCENE_MAX_TURNS` (integer 1–100), and `PRESENT_NATIVE_SCENE_BUDGET_ROOM` (exact room ID). It reserves synchronously, atomically and durably before each actual Codex `turn/start`, including repairs and research follow-ups in that request context. Discovery does not count. The ledger survives restart and contains only scope/hash/count, timestamp and hashes of request/exact-model metadata. Scope/max mismatch, invalid files, exhaustion, concurrent or crash-retained locks fail before dispatch. Reservations are conservatively never refunded if a send fails or a turn is interrupted. A persistent lock after an operator crash therefore requires private operator inspection; there is no API/reset operation. No fence is enabled by default, and unrelated rooms are outside its scope. The matching smoke room requires the Codex transport with Decisions explicitly off and rejects work, delegated research, search and media results before any separate provider operation. Native scene plans and scene controls remain allowed. This bounds the selected smoke room; it is not an account-wide spend limit. Outside that explicitly configured room, product routing remains unchanged.

Scene application retains revision-based transaction deduplication. Its additive, optional causal request ID affects instrumentation only. Native transaction receipts are emitted after successful commit, include replay status and clock, and are excluded for temporary draft-preview writes. A failed transaction emits no commit receipt. The `scene_committed` event follows the atomic scene transaction; `completed` means the room-request function completed, not disk fsync, peer delivery, playback completion, or completion of a delegated research/work task.

The public synthetic Decisions fixture captures exactly 20 real Jev 1.13.0 requests from 2026-10-12 at 22:26–22:27 Pacific. There were 20 HTTP 200 responses and zero deadline, auth or protocol errors. The accepted code's 800 ms route deadline and 0.9 gate were fixed before the run. Resulting plans matched all 20 fixed labels: eight actionable plans and twelve defers, with no room actions applied. Raw route choice matched 18 labels. Missing quoted sticky-note content (0.80 confidence) and a compound right/down move (0.57) were raw route errors stopped by the existing gates. Both original/reversed option-order pairs agreed. Observed p50 was 74.73 ms, p95 139.75 ms, p99/max 196.98 ms using nearest-rank sample statistics; usage was 18,053 input and 3,723 output tokens.

This purposively selected 20-sample pilot does not establish launch accuracy, calibration of 0.9, rare unsafe acceptance, option-order invariance, or production tail latency. Repeated order pairs are not independent. Distribution concentration is not workflow correctness. The recorded Brier/log-loss/reliability bins are descriptive pilot diagnostics; no threshold was tuned or proposed from them. Future promotion needs independently labeled representative development/holdout requests, argument-level results, command-family coverage, unsafe acceptance uncertainty, abstention and load/network tails.

Reproduce the **offline route replay**, with zero network or paid calls:

```sh
node --import tsx scripts/benchmarks/decisions-preflight.ts
node --import tsx --test tests/decisions-preflight.test.ts tests/request-trace.test.ts tests/request-trace-room.test.ts tests/native-scene-budget.test.ts
```

The replay feeds the retained public responses through the literal accepted `judge()` contract and its existing confidence gate. It checks request payload hashes and the recorded route composition. It reports raw versus gated **route** scores separately. The original live receipts also record exact expected/observed arguments; the offline route command does not claim to rerun live timing or argument-level accuracy. No environment file or working API key is needed. The retained public fixture includes synthetic inputs/questions/probabilities/version/request hashes and clocks; it contains no user room data or provider secrets.
